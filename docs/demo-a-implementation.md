A 的点按先显示圆圈，后台对照片编码一次、串行处理当前点，成功后淡入轮廓。页面显示下载字节、准备阶段和实际完成点数。整墙白点扫描与同色涟漪在 B；现有保存确认动画表示保存完成。

## 工程范围

- **数据**：冻结清洗后版本的 SwiftData 存储布局为 V1；V2 增加墙的模型版本。Hold JSON 兼容旧 `id/x/y/r`，新增可选多边形、手脚落点、模型版本和主动保留圆圈的选择。轮廓最多 64 顶点；无有效轮廓继续使用原圆圈。
- **模型下载**：三个 FLOAT16 包共 79,644,968 字节。固定源版本、文件大小与 SHA-256；临时目录逐文件校验，完整后才移入就绪目录。中断重试复用已验证文件，支持取消。下载和编译产物不进入设备备份；没有自动网络下载。
- **推理**：Core ML 在串行 actor 中编译／加载模型，缓存当前照片编码；点提示仅取点击所在连通区域，面积为圆圈的 0.12–4 倍，失败保留圆圈。轮廓提取后继续检查包含点击位置，落点保持在形状内。
- **修改保护**：推理队列绑定照片代次及点的请求快照；删除、移动、改半径、重拍或主动选择圆圈后，旧结果不能覆盖新输入。长按可改回圆圈或重抠单点。
- **旧线转换**：线路页主动转换已有圆圈，只替换仍未改动的几何，不改变 Hold ID、起步／结束、掉落记录和计划／实际。转换支持撤销，离开页面停止后续回写。
- **共用渲染**：建线、首页、线路页、记录、顺序和分享沿用同一聚光灯组件；遮罩、描边、光晕和起步环使用多边形，结束旗／编号／掉落点沿形状边界放置，手脚吸附使用独立落点。圆圈到轮廓使用淡入，兼容减弱动态。
- **导出与恢复**：JSON 版本升为 2，保留轮廓、墙版本及 `reminderSnapshot`。持久库打开失败显示重试入口，保留原库和照片。

## 验证

本机验证日志、结果包和私人模型输入在被忽略的 `.scratch/demo-a-2026-10-05/`。最终完整回归：**185 项单元／集成测试、4 条原生 UI 测试通过，1 项私人真机模型集成测试跳过**，无失败。覆盖旧库迁移、提醒与引用保留、下载中断／取消／校验、过期结果、长轮廓吸附、旧线转换撤销及未下载时保存照片线。模拟器测量不等于 iPhone 性能验收。

Release 在模拟器及 `generic/platform=iOS` 两个目标均构建成功；后者只确认 iPhone SDK 编译，未签名安装到真机。日志分别为 `release-simulator.log` 和 `release-device.log`。JSON 导出的非空提醒快照与轮廓回读断言加强后，相关测试另行通过。

实际运行共享的 App 推理源码，Mac 上 24 个既有点位得到 21 个合格轮廓；单点完整链路中位 21.0 ms、最大 133.6 ms。两个编码耗时分别为 5.135 s 和 0.168 s，包含首次预测的额外开销；不能只摘取较快的一次。21/24 仍是候选通过包含点击及面积筛选的数量，不是人工真值准确率。

**模拟器限制**：Xcode 27 / iOS Simulator 26.5 中，实际模型的遮罩解码输出全零，并记录 `conv_transpose` 动态形状编译异常。CPU 路径与 reshape 提示也未修复；相同源码在 Mac 可以输出轮廓。[上游 iPhone 支持讨论](https://github.com/huggingface/sam2-studio/issues/24#issuecomment-2496562248) 也有真机可运行、模拟器失败的报告。这是定位依据，不能证明本 App 的真机兼容性。App 对全零输出显示识别失败并保留圆圈。

模拟器跳过 1 项私人原生模型集成测试，保留此前失败日志；逻辑／迁移／下载及手动 UI 回归正常执行。真机测试需在 App 的 `Application Support/HoldIntegrationFixtures` 放入私人 `real-cases.json` 和相应图片，并先通过 App 下载模型。没有这些输入时也跳过。照片、点坐标、模型权重和生成图像不随测试源码提交。

可用 [native-check.sh](../experiments/hold-segmentation/native-check.sh) 在 Mac 重跑 **App 共用推理源码**，不是旧原型：

```sh
bash experiments/hold-segmentation/native-check.sh \
  .scratch/hold-seg-proto/input/real-cases.json \
  .scratch/models/coreml-sam2.1-tiny
```

输出仅包含版本、候选数量及聚合时长。程序验证每条输入线至少有一个有效轮廓、点击位置及落点在轮廓内、顶点数 ≤64；输入和模型路径由调用方提供。

## 下一步：真机与馆访

- iPhone 13 或更新设备：分别记录首次模型编译、暖启动照片编码、完整单点链路和峰值内存；门槛为编码 ≤1.5 s、单点 ≤150 ms、峰值 ≤400 MB。不要从 Mac 或模拟器推定达标。
- `HoldSegmentationSession.encodingSeconds` 与 `pointSeconds` 可在调试器查看编码及点链路耗时；首次编译与峰值内存用 Instruments 独立记录。单点运行配置沿用上游 iPhone 实现的 CPU/GPU 路径；真机结果出来前不声称达到速度门槛。
- 在 3 面真实墙比较圆圈与轮廓，主观观感 ≥8/10，建线不比圆圈慢；至少一次馆访，同时验证 v1.1 记忆闭环。
- 记录到 `docs/field-notes/YYYY-MM-DD.md`，模板见 [v1.1 §10.4](linewise_prd_v1_0.md#104-馆访反馈模板)。未过门槛，按 PRD 降级；B–D 继续等待。

## 模型来源

使用 [Apple 的 Core ML SAM 2.1 Tiny FLOAT16 转换](https://huggingface.co/apple/coreml-sam2.1-tiny)，固定 revision `39ae0a8a83e5e6cd196e804bf7cccc5f8171f306`。模型卡标注 Apache 2.0；上游算法及许可见 [facebookresearch/sam2](https://github.com/facebookresearch/sam2)。App 设置页提供来源入口，仓库只保存下载目录和校验摘要。迁移方案参考 [Apple 的 SwiftData schema migration 说明](https://developer.apple.com/videos/play/wwdc2023/10195/)。
