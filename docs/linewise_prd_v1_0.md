## 1. 一句话与问题

**一句话**：线感把一面墙暗下去，只留下你要爬的那条线，然后把你在这条线上每一次的"掉在哪、为什么、下次试什么"存起来，让下一次进馆先看这一眼。

**真实痛点**（来自主要用户的自述与研究报告）：

| 编号 | 痛点 | 今天怎么凑合 | 凑合的代价 |
| --- | --- | --- | --- |
| P1 | 一面墙好多线，事后照片里认不出哪条是我的 | 拍照存相册，靠记忆 | 一周后失效 |
| P2 | 相邻两条同色线认错 | 记"左边那条蓝" | 换线后失效 |
| P3 | 建记录太慢，馆内不想掏手机 | 不记，或回家凭印象记 | 掉在哪、为什么全丢 |
| P4 | 进馆前不知道先磕哪条 | 到了再看 | 热身完才想起来 |
| P5 | 一周后忘了上次卡在哪 | 重新掉一次才想起 | 浪费 2–3 次尝试 |
| P6 | 朋友教的那句话忘了 | 微信里翻 | 找不到 |
| P7 | 架手机录视频回看太低效、占存储 | 录了不看 | 白录 |
| P8 | 掉了不知道为什么（新手） | 归结为"没力" | 反复同一个错 |
| P9 | 不知道自己长期的短板 | 感觉 | 训练无针对性 |
| P10 | 新手不会读线，老手读了留不下来 | 站在墙下比划 | 上墙就忘 |
| P11 | 上了之后"我是怎么上的"没留下 | 无 | 再磕同难度时不能复用 |
| P12 | 提醒/心得没验证，不知道哪句真管用 | 无 | 累积一堆没用的"感觉" |
| P13 | 看不见进步，坚持不下来 | 看难度数字 | 难度数字进步慢 |
| P14 | 线拆了、换线周期后记录乱 | 无 | 历史失去意义 |
| P15 | 想给朋友看今天磕下来的线 | 发照片 | 照片里看不出线 |
| P16 | 以后想做识别，没有自己的标注数据 | 无 | AI 阶段从零开始 |

## 2. 目标用户与场景

### 2.1 用户

两类都服务，不做取舍：

| 用户 | 特征 | 最需要 | 会不会用 |
| --- | --- | --- | --- |
| 有热情的新手（1–12 个月） | 每周 1–2 次，V0–V3，什么都想搞清楚 | 知道为什么掉、学会读线 | 热情高，愿意复盘 |
| 有习惯的老手（1 年以上） | 每周 2–3 次，反复磕同一条 project | 记住卡点和那句话，看见进步 | 复盘是习惯，只要够快 |

不服务（本版）：教练、岩馆运营、绳索攀岩、户外。

### 2.2 三个时刻

| 时刻 | 用户在做什么 | 手的状态 | 能接受的操作 |
| --- | --- | --- | --- |
| 进馆前 / 热身时 | 决定先磕哪条 | 干净 | 看，滑几下 |
| 攀爬中 | 掉下来、休息、再上 | 镁粉、汗、手机在包里 | 0–1 下，或者完全不动 |
| 爬完 / 回家路上 | 复盘今天 | 干净 | 每条线 4–8 下，1–2 分钟 |

产品的所有设计都围绕"攀爬中可以不碰、爬完 2 分钟内记完、进馆前一眼看到"。

### 2.3 环境约束

- 岩馆灯光偏色、逆光、墙面反光：手动点亮不受影响，识别（M3）要考虑。
- 部分岩馆不允许拍照：必须支持无照片的线。
- 无网络或弱网：全部功能本地可用。
- 手上有镁粉：馆内按钮大、少、可撤销。

## 3. 产品原则

1. **聚光灯是唯一视觉母题。** 一条线 = 一面暗下去的墙 + 亮着的那几个点。所有屏幕都是这张图加一件事。
2. **一切按线组织，没有"按天"。** 日期是线路历史里的一个筛选条件，不是一级视图。
3. **建议，不判定。** 系统不判断你上没上、不判断能不能够到、不演示怎么爬。所有系统产出都是可改的建议。
4. **总结只来自你自己的记录。** 教练几句话只引用你自己在这条线上记过的东西；不从体型或照片推导"该怎么爬"。
5. **操作预算是硬指标。** 建一条线 ≤ 15 秒，记一次 ≤ 4 下，馆内可以一下都不按。
6. **本地优先，无账号。** 数据在手机上；分享是导出图片，不是上传。
7. **简约、有特色、突出重点。** 少一屏比多一屏好；每屏一个重点；动效只用在"点亮"这一刻。
8. **可演示优先。** 每个迭代以一个能在岩馆里用的 Demo 结束，用真实馆访反馈决定下一步。

## 4. 核心概念与数据模型

### 4.1 概念

| 概念 | 一句话定义 | 备注 |
| --- | --- | --- |
| 岩馆 Gym | 一个名字 | 手动输入，不用 GPS |
| 墙 Wall | 一张墙照片 + 所属岩馆 + 可选墙区名 + 可选角度 | 一张照片代表一面墙，可承载多条线 |
| 线 Line | 墙上被选中的一组点 + 起步点 + 结束点 + 难度 + 状态 | 一张卡 = 一条线；也可以是无照片的线 |
| 点 Hold | 线上的一个位置（照片归一化坐标 + 半径）+ 自动编号 | 编号从下到上，供掉落点、顺序、备注共用 |
| 攀爬记录 Session | 某一天在某条线上的一次记录 | 一次馆访一条，可展开到每次尝试 |
| 尝试 Attempt | 记录里的一次尝试（可选展开） | 掉在哪个点、上了没 |
| 提醒 Reminder | 这条线最近一次有内容的记录拼成的一句 | 掉哪 · 原因 · 下次试什么，可改 |
| 验证 Check | 下一次记录时对上次提醒的回答 | 有用 / 没变化 / 问题变了 / 没试；记在新记录上，连同当时的提醒原文 |
| 顺序 Sequence | 火柴人的一串步骤 | 分"计划"和"实际"两份 |
| 快照 Snapshot | 顺序里的一步：哪只手脚到哪个点 + 身体姿态 | 胶片条的一格 |
| 分享图 ShareCard | 一张由线路信息生成的图片 | 导出，不上传 |

### 4.2 数据结构

```
Gym
 └─ Wall（照片、墙区、角度、拍摄日期、是否已换线）
     └─ Line（点集合、起步、结束、难度文本、主观难度、状态、创建日期、备注）
         ├─ Reminder（文本、生成于哪条记录、是否已验证）
         ├─ Sequence[plan]  ── Snapshot[]
         ├─ Sequence[actual] ── Snapshot[]
         └─ Session[]（日期、尝试次数、是否上了、掉在哪个点/第几步、原因、下次试什么、对上次提醒的回答 + 当时的提醒原文）
              └─ Attempt[]（可选展开：序号、结果、掉在哪个点）
```

### 4.3 字段规范

**Wall**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 本地 UUID |
| `gym_id` | 是 | 所属岩馆 |
| `photo_ref` | 否 | 本地照片引用；无照片墙允许存在 |
| `area_name` | 否 | 墙区名，如"斜板墙" |
| `angle` | 否 | `slab` / `vertical` / `overhang` / `roof` / `unknown` |
| `shot_at` | 是 | 拍摄或创建时间 |
| `reset_at` | 否 | 标记整面墙已换线的时间 |

**Line**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | 本地 UUID |
| `wall_id` | 是 | 所属墙 |
| `holds` | 否 | `[{index, x, y, r}]`，归一化坐标；无照片线为空 |
| `start_hold_indices` | 否 | 起步点（1–2 个） |
| `finish_hold_index` | 否 | 结束点 |
| `grade_text` | 否 | 文本，如 "V4" / "5" / "紫色" |
| `grade_source` | 否 | `ocr` / `manual` |
| `felt_grade` | 否 | 主观难度：偏软 / 正常 / 偏硬 |
| `status` | 是 | `projecting` / `sent` / `dropped` / `gone` |
| `cycle` | 是 | 第几轮，从 1 开始；"再磕一轮"加 1 |
| `name` | 是 | 默认"墙区 · 日期"，可改 |
| `note` | 否 | 自由文本 |
| `created_at` / `updated_at` | 是 | |
| `merged_into_line_id` | 否 | 被合并到哪条线 |

**Session**

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `id` | 是 | |
| `line_id` | 是 | |
| `date` | 是 | 用户可改的日期，默认当前本地日期 |
| `attempt_count` | 是 | 默认 0；馆内 +1 累加 |
| `sent` | 是 | 布尔 |
| `fall_hold_index` | 否 | 掉在哪个点 |
| `fall_step_index` | 否 | 掉在顺序第几步（有计划时） |
| `reason` | 否 | 见 4.4 |
| `note` | 否 | 下次试什么（一句话），语音转文字或打字 |
| `check` | 否 | `worked` / `no_change` / `different_problem` / `not_tested` |
| `reminder_snapshot` | 否 | 回答 `check` 时被验证的那句提醒原文；提醒之后被换掉，验证仍可追溯 |
| `source` | 是 | `in_gym` / `after` / `backfill` |
| `attempts` | 否 | 展开时的每次尝试 |

### 4.4 原因列表（8 选 1）

| 值 | 显示 | 含义 |
| --- | --- | --- |
| `sequence` | 顺序 | 手脚顺序错了 |
| `feet` | 脚 | 踩不住、脚滑、脚位不对 |
| `body` | 身体 | 重心、贴墙、翻身 |
| `timing` | 时机 | 动态动作时机 |
| `reach` | 够不着 | 距离、锁定 |
| `fear` | 不敢 | 心理 |
| `power` | 没力 | 体能、耐力 |
| `unknown` | 不知道 | 允许选 |

只选一个主要原因。多选延后。

### 4.5 状态流转

```
                 标上了          再磕一轮
projecting ───────────► sent ──────────► projecting (cycle+1)
    │                     │
    │ 放弃                │ 没了
    ▼                     ▼
 dropped ──────► gone ◄────┘
    │ 再磕一轮
    └──────────► projecting (cycle+1)
```

- `gone` 是终态之一，但历史保留；同墙"整面换线"可批量置 `gone`。
- 任何状态变更可在 5 秒内撤销。

## 5. 场景与流程

每个场景写清：触发 → 步骤 → 系统行为 → 结束状态 → 分支。

### 5.1 首次打开

- **触发**：安装后第一次打开。
- **步骤**：一屏引导（三句话：拍一面墙 → 点亮你的线 → 记下掉在哪），底部一个按钮"拍第一面墙"。不注册、不登录、不要权限。
- **系统**：点击按钮时才请求相机权限；拒绝则进入"无照片建线"分支。
- **结束**：进入建线流程。
- **分支**：用户先想看看 → 允许跳过，首页空态仍是一个"拍墙"按钮。

### 5.2 建线 A：拍新墙

- **触发**：首页"+"或空态按钮。
- **步骤**：
  1. 相机取景，拍一张墙（横竖均可）。
  2. 照片整体暗下去（蒙版），提示"点亮你的线"。
  3. 逐个点点：每点一下出现一个亮圈和编号；再点一下灭。可双指缩放看细节。
  4. 系统默认最低点为起步、最高点为结束，用双环和旗标标出；长按某点可改起步/结束。
  5. 点"完成"：一道光从下到上扫过，点依次亮起、编号浮现（扫描动效，≈1.2 秒，尊重系统"减弱动态效果"）。
  6. 建卡完成，进入线路页；名字默认"墙区 · 日期"。
- **系统**：若照片中有可识别的难度标签，OCR 结果预填 `grade_text`，标注"自动读取，点击修改"。墙区默认上次用的；角度默认 `unknown`。
- **结束**：Wall + Line 创建；操作预算 ≈ 拍 1 + 点亮 5–8 + 完成 1。
- **分支**：
  - 只点了 0–1 个点就完成 → 允许，提示"以后可以补点"。
  - 拍歪/拍虚 → 允许重拍，重拍替换照片（此时还没有线依赖它）。

### 5.3 建线 B：已有墙上加一条线

- **触发**：线路页 → "这面墙上再建一条"；或首页"+" → "选已有的墙"。
- **步骤**：列出这个岩馆最近的墙（缩略图为原照片，不暗化）；选一面 → 进入 5.2 的第 2 步。
- **系统**：新线复用同一张照片；两条线各自的聚光灯图不同。
- **结束**：同一 Wall 下第二条 Line。

### 5.4 建线 C：认旧线

- **触发**：进入已有墙时。
- **步骤**：系统先列出这面墙已有的线（每条一张聚光灯缩略图 + 状态）。用户点选 → 直接进线路页；点"都不是" → 新建。
- **M3 增强**：拍新照片时，用点集合相似度提示"这可能是 X 线"，用户确认或忽略。
- **结束**：不产生重复卡。认不出就新建，接受重复，后续可合并（5.13）。

### 5.5 建线 D：无照片

- **触发**：岩馆禁止拍照、相机权限被拒、光线太差。
- **步骤**：选"不拍照"，填墙区、颜色/标签文字、难度；卡片用纯色暗底 + 文字。
- **系统**：`holds` 为空；掉在哪退化为文字输入；顺序功能不可用（灰显并说明）。
- **结束**：可记录、可复盘，缺聚光灯图。

### 5.6 馆内记录（攀爬中）

- **触发**：线路页 → "记录"区，或从首页卡片直接操作。
- **步骤**：一个大 `+1` 和一个 `上了` 开关；每次掉下来点一下（或不点）。
- **系统**：立即落盘（防止 App 被杀）；每次 +1 可撤销 5 秒；今天没有记录时自动创建今天的 Session。
- **结束**：`attempt_count` 累加、`sent` 置位、`source = in_gym`。
- **分支**：完全不记 → 爬完补记时直接填次数。

### 5.7 爬后补记（当天或之后）

- **触发**：线路页 → "记这一次"；或首页"今天"筛选下逐条进入。
- **步骤**（按价值排序，全部可跳；首屏规则见 6.4）：
  0. 上次这句有用吗？（这条线有更早记录留下的提醒时才出现，一下）
  1. 掉在哪：点聚光灯图上的点；或有计划顺序时点某一步（图固定在上半屏）。
  2. 上了吗。
  3. 为什么掉：8 选 1。
  4. 下次试什么：一句话，语音转文字或打字。
  5. 试了几次（馆内点过则预填）。
  6. 日期：默认今天，放在最后，可改到任意过去日期。
- **系统**：存完自动拼提醒："掉在 ⑤ · 脚 · 右脚先踩高再出手"，可改；`source = after` 或 `backfill`（改过日期）。第 0 步的回答写进这条新记录（`check` + `reminder_snapshot`），**先记验证、再换提醒**，所以新记录里写了内容也不会冲掉对上一句的验证。
- **结束**：Session 落盘；Reminder 按 5.9 更新。
- **分支**：
  - 上了且没掉 → 跳过掉哪/原因，只写下次试什么（或什么都不写）。
  - 想记每一次尝试 → 点"展开"，变成每次一行（序号、结果、掉哪）。
  - 一天磕了同一条线两段 → 仍是一条 Session，次数累加。
  - 改的是提醒来源那条记录本身，或日期早于它 → 不问第 0 步。

### 5.8 进馆前查看

- **触发**：打开 App。
- **步骤**：首页横滑，一屏一条线。每张卡显示：聚光灯图（上次掉的点画在图上）、墙区·难度、第几次来、提醒。提醒里已有掉哪·原因时，文字不再重复一遍。
- **系统**：默认筛当前岩馆 + `projecting`；排序：最近有记录的优先。
- **结束**：用户决定先磕哪条，不需要点进去。

### 5.9 提醒验证

- **触发**：一条线在有提醒的情况下产生新 Session。
- **步骤**：主入口是"记这一次"第 0 步（5.7），在用户本来就在复盘的时候问，一下。兜底入口是线路页提醒区：只在馆内点过 `+1`、还没进"记这一次"的记录上出现同一个问句。
- **规则**（只有两条）：
  1. 验证记在新记录上：`check` + 当时的提醒原文 `reminder_snapshot`。回答"有用"时，这句提醒标 ✓。
  2. 提醒永远是**最近一次有内容的记录**拼出来的。新记录有内容 → 提醒换成新的（旧的那句和它的验证留在历史里）；新记录没内容 → 旧提醒保留。
- **结束**：提醒带"已验证 ✓ 有用"，或换成新的一句。
- **分支**：不回答 → 不阻塞；新记录有内容时提醒照常更新，这次就算没验证。

### 5.10 状态流转

- **标上了**：线路页状态行 → "上了"。若当天 Session 的 `sent=false`，同时置 true。
- **放弃**：→ `dropped`；卡片从"进行中"筛选中消失，仍可在"全部"找到。
- **没了**：→ `gone`；灰化卡片；历史保留。
- **再磕一轮**：`sent`/`dropped` → `projecting`，`cycle+1`；历史分轮显示。
- **整面墙换线**：墙页 → "这面墙换线了" → 该墙所有非 `gone` 线批量置 `gone`（二次确认，可撤销）。

### 5.11 线路页复盘

- **触发**：点进任一条线。
- **步骤**：上半屏聚光灯图（叠历史掉落点，颜色由浅到深表示时间）；下半屏依次：状态行、提醒与验证、记录、教练几句、顺序、历史、分享。
- **历史**：每次 Session 一行（日期 · 次数 · 掉哪 · 原因 · 一句话），顶部日期范围筛选 + 轮次筛选；点一行展开每次尝试。
- **教练几句**（M1）：2–3 句，只引用本线记录。模板：
  - "你在 ⑤ 掉了 3 次，前两次说是脚。"
  - "上次提醒是'右脚先踩高'，还没回答有没有用。"
  - "这条线你来了 4 次，从第 2 次起没再掉在 ③。"
- **结束**：用户知道下次试什么。

### 5.12 顺序：火柴人（M2）

- **触发**：线路页 → 顺序 → "计划"或"实际"。
- **布局**：聚光灯图占满上方，快照排成底部横向胶片条（UI 规范 §4.5；竖屏左右分栏会让画布小到没法拖）。
- **开始**：火柴人自动放置，双脚站地面，双手在起步点上；这是第 0 格。
- **每一步**：拖一只手或脚到某个亮点，松手吸附最近的点，身体自动跟随；胶片条追加一格（小图 + "左手→③"）。
- **结束**：双手都到结束点 → 自动标"完成"，最后一格带勾。
- **改**：点胶片条任一格 → 图回到那一步；从这里再拖 → 后面的格子被替换（浏览器历史式）。
- **撤销**：撤销最后一格。
- **身体**：只跟随，不判断。不提示"够不着"、不计算重心、不评分。
- **计划 → 实际**：上了之后点"复制为实际" → 复制一份改几步；线路页并排两列，不同的格子标出。
- **回放**：胶片条本身可滑；另有一个播放键逐格回放。只在用户点了才播，每格停顿，不插值成连续动画，编辑或拖动时立即停。
- **掉在第几步**：5.7 里可直接点某一格作为掉落位置。
- **体型**（可选，M2）：身高、臂展两项，只影响火柴人比例；不填用默认。
- **无照片线**：顺序不可用。

### 5.13 合并重复卡

- **触发**：线路页 → 更多 → "这其实是另一条线"。
- **步骤**：选目标线 → 确认 → 本线所有 Session 迁移到目标线，本线标 `merged_into_line_id`。
- **系统**：保留被合并卡的聚光灯图作为目标线的"备选照片"；可撤销一次。

### 5.14 分享

- **触发**：线路页 → 分享。
- **步骤**：生成竖图 → 系统分享面板。
- **内容**：聚光灯线路图 + 三行字（墙区·难度·状态；来了 N 次·共 M 次尝试；那一句提醒）+ 一条横向快照带：有实际顺序时是顺序快照（默认带，可关）；没有时是这条线的馆访快照（每次一格：次数、掉在哪）。两种都按线组织，不是按天的时间线海报。
- **系统**：本地渲染，不上传。提示"照片里如有他人请注意隐私"（首次）。

### 5.15 换岩馆 / 多馆

- **触发**：首页顶部岩馆名。
- **步骤**：切换或新建岩馆（只填名字）。
- **系统**：所有筛选默认当前岩馆；"全部岩馆"可选。

### 5.16 数据管理

- **导出**：设置 → 导出 → 生成 zip（JSON + 照片）→ 分享面板。`MVP` 只要 JSON（便于自测诊断），照片打包 `M1`。
- **删除**：单条线删除（软删 + 撤销 5 秒）；删除全部数据（二次确认 + 输入"删除"）。
- **备份/换机**：`MVP` 依赖 iOS 系统备份；`M3` iCloud 私有库同步。
- **权限**：只请求相机、（可选）语音识别；不请求相册全量、不请求定位。

### 5.17 异常与边界

| 情形 | 行为 |
| --- | --- |
| App 在馆内被杀 | 所有 +1 已落盘，重开无损 |
| 跨午夜 | 日期以用户选择为准；默认取记录创建时的本地日期 |
| 误 +1 / 误标状态 | 5 秒撤销条；历史里也可改数字 |
| OCR 读错难度 | 点一下改；`grade_source` 变 `manual` |
| 墙照片里有其他人 | 分享前首次提示；本地存储不处理 |
| 同一面墙不同日期各拍了一张 | 两面 Wall；不自动合并；M3 相似度提示 |
| 拍照后想换更好的照片 | 该墙上还没有线 → 直接重拍；已有线 → 新建一面墙，旧线不动 |
| 设备存储不足 | 照片按长边 2048 存储，单张 ≤ 1 MB |
| 系统"减弱动态效果"开启 | 扫描动效退化为直接显示 |
| 无网络 | 无任何影响 |

## 10. 敏捷计划：Demo 驱动

### 10.0 当前位置（2026-09-23）

- Demo 0–3 的功能已在 iOS App 里实现，模拟器 156 项单元测试 + 2 条 UI 测试通过（`docs/linewise_status_2026-09-13.md`）。
- **但没有一次真实馆访，也没上过真机。** 按本章规则，没有一个 Demo 的退出标准被满足。
- 因此：**功能冻结**。在 Demo 1 的现场退出标准达成前，不开新功能，只做两类改动：① 修正核心闭环（拍墙 → 记这一次 → 提醒 → 验证）上的错误；② 为上真机、上馆必须补的工程项。
- 下一个 Sprint 是 §10.3 的现场验证，而不是 Demo 4。

### 10.1 节拍

- Sprint 长度：1 周（单人开发）。
- 每个 Sprint 以一个**可在岩馆里真用的 Demo** 结束，Demo 只回答一个问题。
- 每个 Demo 至少经历 1–2 次真实馆访，馆访后 10 分钟填反馈（10.4），再定下一个 Sprint 的内容。
- 需求变化直接改本文档对应章节并在 §17 记一行变更。

### 10.5 度量（只在本机，不上传）

| 指标 | 采集方式 | MVP 目标 |
| --- | --- | --- |
| 建线时长 | 拍照到完成 | 中位 ≤ 15s，P90 ≤ 25s |
| 记这一次操作数 | 打开到保存的点击数 | 中位 ≤ 4 |
| 馆内 +1 使用率 | 有 +1 的 Session / 全部 Session | 观察，不设目标 |
| 进馆前打开 | 当天第一次打开是否在第一条记录之前 | ≥ 50% 的馆访 |
| 提醒回答率 | 有 `check` 的 Session / 保存时已有更早提醒的 Session | ≥ 50%（M1） |
| 复盘完成率 | 有原因或下次试什么的 Session / 全部 | ≥ 60% |
| 线路重访率 | 两次以上 Session 的线 / 全部 `projecting` 线 | ≥ 40% |
| 计划使用率 | 有计划的线 / 尝试 ≥ 3 次的线 | ≥ 30%（M2） |

## 14. 不做与红线

**本版不做**

- 视频录制或导入
- 姿态分析、动作评分、可行性判断
- 火柴人插值连播动画、3D、网格人（逐格回放允许，见 5.12）
- 按天的日志视图、时间线海报、健身圆环
- 社区、动态、点赞、公开 Beta
- 账号、云端 AI
- 岩馆数据库、教练后台、订阅
- Apple Watch（延后到 Demo 5）；多种"采集模式"；Health / FIT / 相册导入
- 搜索（FR-49；可见的线超过 50 条再议）
- 岩点轮廓分割（提案见 `docs/linewise_hold_segmentation_proposal_2026-09-13.md`；等现场证明圆圈导致认错线再做）
- "上了之后自动提示复制计划为实际"（"复制为实际"已在顺序菜单里）
- 生理数据（心率、肌肉负荷）作为核心功能；未来最多作为休息参考

**红线**

- 不请求定位；不请求相册全量访问
- 不做医疗、安全、伤病表述
- 不把系统识别结果当作官方线路
- 不从照片或体型推断用户的能力
- 不在没有用户明确操作的情况下改写用户记录
- 所有系统建议可一下改掉
